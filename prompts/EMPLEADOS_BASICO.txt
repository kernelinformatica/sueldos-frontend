Necesito implementar en mi frontend Angular una pantalla completa para administrar los **Básicos Personalizados de Empleados**.

IMPORTANTE: NO rediseñar la arquitectura existente del proyecto. Adaptarse al patrón, estilos, componentes, servicios, modales, tablas, formularios y manejo de errores que ya utiliza el proyecto.

## Objetivo

Crear una pantalla CRUD para administrar los registros de `empleado_basico`.
creala en modulos/empleados/basicos-personalizados
La pantalla debe permitir:

* Listar básicos personalizados.
* Buscar/filtrar empleados.
* Crear un básico personalizado para un empleado.
* Modificar un básico existente.
* Dar de baja un básico personalizado.
* Seleccionar varios empleados y realizar alta masiva.
* Seleccionar varios registros y realizar modificación masiva.
* Seleccionar varios registros y realizar baja masiva.
* Mostrar claramente si el registro está activo o dado de baja.
* Manejar fechas de vigencia.

## MUY IMPORTANTE: EMPRESA

El backend obtiene la empresa desde el JWT:

```ts
req.user.empresa_id
```

Por lo tanto:

**EL FRONTEND NO DEBE ENVIAR `empresa_id` NUNCA.**

No agregar `empresa_id`:

* ni como campo del formulario,
* ni como query parameter,
* ni dentro del body,
* ni como parámetro manual del usuario.

El token JWT ya contiene la empresa y el backend se encarga de determinarla.

Por ejemplo, para listar:

```http
GET /api/empleado-basico
```

NO:

```http
GET /api/empleado-basico?empresa_id=1
```

El `Authorization: Bearer <token>` debe ser manejado por el mecanismo de autenticación/interceptor existente del proyecto.

# ENDPOINTS DISPONIBLES

Usar estos endpoints:

### Listar

```http
GET /api/empleado-basico
```

Opcionalmente:

```http
GET /api/empleado-basico?activo=1
```

Respuesta esperada:

```json
{
  "success": true,
  "data": [
    {
      "empleado_basico_id": 1,
      "empresa_id": 1,
      "empleado_id": 25,
      "basico_personalizado": 850000,
      "fecha_desde": "2026-10-01",
      "fecha_hasta": null,
      "activo": 1,
      "apellido": "Pérez",
      "nombre": "Juan",
      "documento": "30111222",
      "legajo": "125"
    }
  ]
}
```

Aunque el backend devuelve `empresa_id`, el frontend solamente lo puede mostrar si es necesario. NO debe utilizarlo para construir requests.

### Obtener un registro

```http
GET /api/empleado-basico/:id
```

### Obtener básicos de un empleado

```http
GET /api/empleado-basico/empleado/:empleadoId
```

### Crear

```http
POST /api/empleado-basico
```

Body:

```json
{
  "empleado_id": 25,
  "basico_personalizado": 850000,
  "fecha_desde": "2026-10-01",
  "fecha_hasta": null,
  "activo": 1
}
```

### Modificar

```http
PUT /api/empleado-basico/:id
```

Body:

```json
{
  "empleado_id": 25,
  "basico_personalizado": 900000,
  "fecha_desde": "2026-10-01",
  "fecha_hasta": null,
  "activo": 1
}
```

### Baja individual

```http
DELETE /api/empleado-basico/:id
```

La baja es lógica. El backend establece:

```text
activo = 0
```

No eliminar físicamente el registro desde el frontend.

### Alta masiva


Body:

```json
    {
      "empleado_id": 10,

```

### Modificación masiva

```http
PUT /api/empleado-basico/masivo
```

Body:

```json

    {
      "empleado_basico_id": 15,
```
